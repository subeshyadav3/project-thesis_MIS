1. High-Level Architecture & Core Concepts

In modern web applications built on Node.js and Express, dealing with files involves three major operational pillars:

Pillar 1: File Ingestion (HTTP Multipart Ingestion)

Receiving binary data from clients via standard HTML forms or AJAX requests using multipart/form-data format, handled by Multer middleware in memory without polluting disk with temporary files.

Pillar 2: File Parsing & Data Extraction

Converting unstructured or tabular binary formats (such as Excel .xlsx sheets or PDF/Word documents) into structured JS objects using dedicated libraries like SheetJS (`xlsx`), `pdf-parse`, or `mammoth`.

Pillar 3: File Generation & Rendering

Dynamically assembling data from database queries (via Prisma ORM) into custom HTML/CSS templates, rendering them using a headless browser engine (Puppeteer), and streaming the resulting PDF binary directly back to the HTTP client with appropriate headers.

2. Multer & In-Memory Binary Stream Theory

Standard JSON endpoints accept application/json text payloads. However, when uploading files, browsers wrap payload parts in boundary strings under multipart/form-data.

Express by default does not parse multipart body streams. Multer is a Node.js middleware for handling multipart/form-data.

Disk Storage vs. Memory Storage

Feature Disk Storage (multer.diskStorage) Memory Storage (multer.memoryStorage) — Used Here
Data Location Saves uploaded file to disk at /tmp/upload_1234. Holds file in RAM as a JavaScript Buffer object.
Performance Slower (involves disk I/O write then read). Lightning fast (direct RAM access via req.file.buffer).
Cleanup Requires manual garbage cleanup of temp files. Automatically garbage-collected when request ends.
Usage in Project Not used for initial parsing. Used across all Excel import routes & upload controllers.

How Multer Attaches File Metadata to req.file

Exact Code Implementation (userController.js)

exports.bulkImportUsersExcel = async (req, res) => {
  try {
    if (!req.file) return res.status(400).json({ error: 'No file uploaded' });

    const XLSX = require('xlsx');
    
    // 1. Parse raw binary buffer directly from RAM
    const workbook = XLSX.read(req.file.buffer, { type: 'buffer' });
    
    // 2. Target the first worksheet
    const sheet = workbook.Sheets[workbook.SheetNames[0]];
    
    // 3. Convert tabular cells into array of objects [{ rollNumber: '080BCT001', firstName: 'Ram' }]
    const rows = XLSX.utils.sheet_to_json(sheet);

    // 4. Iterate and insert records
    for (let i = 0; i < rows.length; i++) {
      const row = rows[i];
      const rollNumber = row.rollNumber || row.RollNumber;
      const email = rollNumber.toLowerCase() + '@pcampus.edu.np';
      const hash = await bcrypt.hash(row.password || 'default123', 10);

      await prisma.user.create({
        data: { email, password: hash, firstName: row.firstName, lastName: row.lastName, rollNumber, role: 'STUDENT' }
      });
    }
    
    res.status(201).json({ success: true, created: rows.length });
  } catch (err) {
    res.status(500).json({ error: err.message });
  }
};

4. Flow 2: Proposal Document Upload & Magic Bytes

File extensions can be forged by renaming malicious files (e.g. exe to .pdf). To prevent security vulnerabilities, uploadController.js inspects binary magic bytes at the buffer level.

Magic Byte Signature Map

Format Header Hex Bytes ASCII Equivalent Validation Logic
PDF 0x25, 0x50, 0x44, 0x46 %PDF Matches first 4 bytes of buffer
DOCX / XLSX 0x50, 0x4B, 0x03, 0x04 PK\x03\x04 (Zip archive header) Matches first 4 bytes of buffer
DOC 0xD0, 0xCF, 0x11, 0xE0 Compound File Binary Matches legacy OLE header
PNG 0x89, 0x50, 0x4E, 0x47 \x89PNG Matches PNG header

Signature Checking Code

function detectMimeFromBuffer(buffer) {
  for (const [type, signatures] of Object.entries(MAGIC_SIGNATURES)) {
    for (const sig of signatures) {
      const matches = sig.bytes.every((byte, i) => buffer[sig.offset + i] === byte);
      if (matches) return type;
    }
  }
  return null;
}

Puppeteer Service Implementation (printController.js)

async function generatePdf(html) {
  const browser = await getBrowser(); // Shared Chromium process
  const page = await browser.newPage();
  try {
    // Load HTML string into headless DOM
    await page.setContent(html, { waitUntil: 'networkidle0' });
    
    // Print virtual page to A4 PDF Buffer
    const pdf = await page.pdf({
      format: 'A4',
      printBackground: true,
      margin: { top: '20mm', bottom: '20mm', left: '15mm', right: '15mm' },
    });
    return Buffer.from(pdf);
  } finally {
    await page.close(); // Tab cleanup
  }
}

6. Flow 4: Background AI Extraction (`pdf-parse`)

When a proposal PDF is uploaded, the main HTTP request must return immediately without keeping the user waiting. The project uses non-blocking asynchronous execution via setImmediate() to trigger background AI parsing.

Asynchronous Non-Blocking Pattern (uploadController.js)

function triggerAIChatbot({ proposalId, documentUrl, documentType, authToken }) {
  const fetchAndLog = async () => {
    try {
      // Calls background AI service endpoint
      await fetch('http://localhost:8001/api/ai/analyze', {
        method: 'POST',
        headers: { 'Content-Type': 'application/json', Authorization: authToken },
        body: JSON.stringify({ proposal_id: proposalId, document_url: documentUrl, document_type: documentType }),
      });
    } catch (e) {
      console.warn('AI service offline:', e.message);
    }
  };

  // Queue function to run on next event loop tick without blocking current HTTP response
  setImmediate(fetchAndLog);
}

In the AI microservice, pdf-parse receives the file path from documentUrl, reads the raw text contents out of the PDF page objects, converts text into vector embeddings, and enables similarity queries for proposal evaluation.
