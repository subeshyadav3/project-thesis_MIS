AXIOS

Mental Model: Talk to APIs

What & Why

What: Axios is a Promise-based HTTP client for the browser and Node.js. It acts as an isomorphic abstraction layer over low-level network APIs.

Why use Axios over native Fetch API?

  • Automatic JSON Transformation: Axios automatically serializes outgoing JavaScript objects into JSON strings and parses incoming JSON responses into objects. Fetch requires explicit res.json() calls.
  • Error Handling Model: Native fetch only rejects a promise on network failures (e.g., DNS lookup failure, offline). It considers HTTP 404 Not Found or 500 Internal Server Error as successful promises. Axios automatically throws errors for HTTP status codes outside the 2xx range.
  • Interceptors: Provides pre-request and post-response middleware hooks globally or per instance (essential for JWT token injection and centralized error handling).
  • Request Cancellation: Native support for AbortController and legacy CancelToken.

How It Works Under the Hood (Deep Theory)

Adapter Pattern & Promise Interceptor Chain

Axios relies on the Adapter Design Pattern to achieve environment polyfill capability. In browser environments, it invokes XMLHttpRequest (or fetch via custom adapters); in Node.js runtime, it uses native http and https modules.

Interceptor Execution Stack: Axios manages two arrays: requestInterceptors and responseInterceptors. When axios.request() is called, it constructs a Promise execution chain:

[...requestInterceptors, dispatchRequest, ...responseInterceptors]

Request interceptors are executed in reverse order of registration (UNSHIFT), mutating the config object before sending. Response interceptors run sequentially (PUSH) processing the resolved AxiosResponse object.

Concise Code Example

axios_example.jsJavaScript
import axios from 'axios';

// Create custom configured instance
const api = axios.create({
    baseURL: 'https://api.university.edu/v1',
    timeout: 5000,
    withCredentials: true // Send HTTP-only cookies across origins
});

// Global Request Interceptor (Inject Auth Header)
api.interceptors.request.use((config) => {
    const token = localStorage.getItem('authToken');
    if (token) config.headers.Authorization = `Bearer ${token}`;
    return config;
});

// Execute API Call
const loginUser = async (credentials) => {
    const { data } = await api.post('/auth/login', credentials);
    return data; // Auto-parsed JSON body
};
💡 Viva & Examination Questions
Q: How does Axios handle HTTP 404 or 500 errors differently from native fetch()?
A: Axios checks the response HTTP status against the validateStatus config rule (default: status >= 200 and < 300). If outside this range, Axios rejects the Promise and throws an AxiosError containing error.response. Native fetch() resolves successfully on HTTP 404/500 and requires manual checks on res.ok.
Q: What design pattern enables Axios to run in both Node.js and Browser?
A: The Adapter Pattern. Axios defines a unified API interface, but delegates the actual execution to environment-specific adapters (adapters/xhr.js for browser XHR and adapters/http.js for Node.js native HTTP streams).

RECHARTS

Mental Model: Draw charts in React

What & Why

What: Recharts is a declarative charting library built specifically for React apps, combining D3 scale primitives with SVG rendering.

Why use Recharts over raw D3 or Canvas Charting (Chart.js)?

  • Declarative Composition: Chart layouts are constructed using pure React sub-components (<XAxis />, <Tooltip />, <Bar />), enabling standard React state/prop updates.
  • Direct DOM / SVG React Harmony: Traditional D3 directly mutates the browser DOM, conflicting with React's Virtual DOM reconciliation mechanism. Recharts uses D3 only for underlying math/scale algorithms while letting React manage the DOM SVG nodes.
  • Scalable Vector Graphics (SVG): Crisp rendering across all pixel densities (Retina displays) and seamless styling via standard CSS.

How It Works Under the Hood (Deep Theory)

Coordinate Mapping & Responsive Container Math

1. Data Key Mapping: Recharts takes an array of JavaScript objects. The dataKey prop extracts numeric fields from objects and passes them through D3 scale modules (e.g., d3-scale-linear, d3-scale-band) to calculate exact pixel coordinates within the SVG viewport.

2. ResponsiveContainer Mechanics: <ResponsiveContainer /> wraps child charts inside an HTML container div and listens to element dimension shifts via ResizeObserver. Upon resize, it recalculates width/height state and triggers a React render pass to recalculate SVG viewBox dimensions dynamically.

Concise Code Example

StudentPerformanceChart.jsxReact Component
import { ResponsiveContainer, BarChart, Bar, XAxis, YAxis, Tooltip, CartesianGrid } from 'recharts';

const data = [
    { batch: '2022', thesesPassed: 42 },
    { batch: '2023', thesesPassed: 58 },
    { batch: '2024', thesesPassed: 75 }
];

export const PerformanceChart = () => (
    <ResponsiveContainer width="100%" height={300}>
        <BarChart data={data}>
            <CartesianGrid strokeDasharray="3 3" />
            <XAxis dataKey="batch" />
            <YAxis />
            <Tooltip />
            <Bar dataKey="thesesPassed" fill="#38bdf8" radius={[4, 4, 0, 0]} />
        </BarChart>
    </ResponsiveContainer>
);
💡 Viva & Examination Questions
Q: What is the main rendering difference between SVG-based Recharts and Canvas-based Chart.js?
A: Recharts renders SVG DOM nodes for every element (bars, axis ticks, tooltips), which makes elements individually inspectable, CSS-styleable, and interactive. Canvas (Chart.js) draws pixels directly on a single bitmap buffer; Canvas is faster for massive datasets (100,000+ points), but SVG (Recharts) integrates superiorly with React UI components and state.
Q: How does ResponsiveContainer calculate dynamic dimensions without triggering endless re-render loops?
A: It uses the browser's native ResizeObserver API on the parent container element, updating internal state only when bounding box client dimensions actually change.

MULTER

Mental Model: Accept uploaded files

What & Why

What: Multer is Node.js middleware for Express that parses incoming HTTP multipart/form-data requests (file uploads).

Why: Standard Express body parsers (express.json() and express.urlencoded()) are strictly designed for URL-encoded forms or raw text/JSON payloads. Binary file uploads require boundary-separated multipart streams, which Express cannot parse natively.

How It Works Under the Hood (Deep Theory)

Busboy Stream Parsing & Storage Engine Trade-offs

Multer wraps busboy, a high-performance streaming parser for Node.js. When an HTTP POST request hits a Multer endpoint, Multer inspects the Content-Type header for a boundary string (e.g., multipart/form-data; boundary=---------------------------12345).

It reads incoming TCP data chunks directly from Node's req stream, splitting binary data at boundary markers into text fields (populated in req.body) and file streams (attached to req.file or req.files).

Storage Strategy Mechanism Pros / Cons
diskStorage Pipes incoming stream directly to disk write streams (fs.createWriteStream). ✅ Low RAM footprint.
❌ Slower I/O latency; leaves temporary disk state.
memoryStorage Buffers entire binary chunk array into RAM heap (Buffer.concat()). ✅ Ultra-fast in-memory parsing (e.g., immediate PDF/Excel processing).
⚠️ High risk of V8 Heap Out-Of-Memory (OOM) crashes under concurrent uploads.

Concise Code Example

uploadRouter.jsExpress Middleware
import express from 'express';
import multer from 'multer';

const router = express.Router();

// Configure Memory Storage strategy with file size guardrails
const upload = multer({
    storage: multer.memoryStorage(),
    limits: { fileSize: 10 * 1024 * 1024 }, // 10 MB limit
    fileFilter: (req, file, cb) => {
        if (file.mimetype === 'application/pdf' || file.mimetype.includes('wordprocessingml')) {
            cb(null, true);
        } else {
            cb(new Error('Invalid file type. Only PDF and DOCX allowed.'), false);
        }
    }
});

// Route definition accepting single file field named "proposal"
router.post('/upload-proposal', upload.single('proposal'), (req, res) => {
    // File buffer accessible in memory: req.file.buffer
    res.json({ status: 'success', filename: req.file.originalname, size: req.file.size });
});
💡 Viva & Examination Questions
Q: What security vulnerability exists if you use memoryStorage for file uploads without size limits?
A: Denial of Service (DoS) via V8 memory exhaustion. If malicious actors upload multiple multi-gigabyte files concurrently, Node.js allocates RAM buffers until the V8 heap crashes with an Out-Of-Memory (OOM) error.
Q: How does Multer split text form fields from binary files in a single HTTP request?
A: It scans the raw incoming TCP request stream for the multipart boundary token specified in the HTTP Content-Type header. Anything delimited before a field header is assigned to req.body, while binary data between boundaries is routed to file streams.

XLSX (SheetJS)

Mental Model: Parse & Produce Excel Files

What & Why

What: SheetJS (xlsx package) is a JavaScript library for parsing, manipulating, and generating OpenXML spreadsheet files (.xlsx, .xls, .csv).

Why: Universities and enterprise systems rely heavily on Excel for bulk data entry (e.g., student batch lists, supervisor assignments, marksheets). Manual parsing of raw compressed OpenXML structures is impossible without a specialized binary/XML AST parser.

How It Works Under the Hood (Deep Theory)

OpenXML Unzipping & Shared String Table Resolution

An .xlsx file is fundamentally a compressed ZIP archive containing a tree of XML documents (e.g., [Content_Types].xml, xl/workbook.xml, xl/worksheets/sheet1.xml, xl/sharedStrings.xml).

Parsing Pipeline:

  1. Decompression: SheetJS decompresses the input binary buffer (using internal JSZip/CFB engines).
  2. Shared Strings Table: Excel saves disk space by storing repeated text strings inside a shared XML lookup table (xl/sharedStrings.xml). Individual sheet cells store zero-based index pointers (e.g., <c t="s"><v>0</v></c>). SheetJS resolves these references back to actual strings.
  3. In-Memory AST: Builds an abstract workbook tree object: Workbook -> SheetNames -> Sheets -> Cell Reference Objects (A1, B1).

Concise Code Example

excelService.jsJavaScript
import * as XLSX from 'xlsx';

// 1. Parse uploaded binary buffer to JSON array
export const parseStudentExcel = (fileBuffer) => {
    const workbook = XLSX.read(fileBuffer, { type: 'buffer' });
    const sheetName = workbook.SheetNames[0]; // Target first tab
    const worksheet = workbook.Sheets[sheetName];
    
    // Convert tabular grid to Array of JavaScript Objects
    const studentRecords = XLSX.utils.sheet_to_json(worksheet);
    return studentRecords; // [{ Roll: 1, Name: "Alice" }, ...]
};

// 2. Export JSON array back into downloadable Excel Buffer
export const exportGradeReport = (reportData) => {
    const worksheet = XLSX.utils.json_to_sheet(reportData);
    const workbook = XLSX.utils.book_new();
    XLSX.utils.book_append_sheet(workbook, worksheet, "Marksheet");
    
    return XLSX.write(workbook, { type: 'buffer', bookType: 'xlsx' });
};
💡 Viva & Examination Questions
Q: What is an .xlsx file actually comprised of under the hood?
A: It is a ZIP container holding structured XML files adhering to the Open Packaging Conventions (OPC). Key files inside include xl/workbook.xml (structure), xl/worksheets/sheet1.xml (cell data), and xl/sharedStrings.xml (string cache table).
Q: Why does Excel use a "Shared String Table"?
A: Optimization of file size. Storing identical strings (e.g., "Pass/Fail" repeated 10,000 times) in a central XML table and referencing them via integer IDs prevents XML bloat.

MAMMOTH

Mental Model: .docx → Clean Text / HTML

What & Why

What: Mammoth is a specialized converter designed to extract text and convert Word document (.docx) files into HTML or plain text.

Why: Standard file stream readers (fs.readFile) read Word documents as unreadable binary data. Mammoth strips heavy, non-standard Microsoft Word layout formatting (margins, fonts, XML metadata) and extracts clean, semantically structured text/HTML suitable for browser display, database indexing, or AI processing pipelines.

How It Works Under the Hood (Deep Theory)

OpenXML Semantic Mapping Tree

Like XLSX, .docx files are compressed ZIP folders containing OpenXML files. Mammoth specifically extracts word/document.xml and word/styles.xml.

Transformation Pipeline:

  1. Unzips file and parses Word XML tags: <w:p> (paragraph), <w:r> (run of text), <w:t> (text node), <w:tbl> (table).
  2. Semantic Translation: Ignores visual attributes (e.g., "Font: Calibri 11pt, Margin: 1 inch") and maps semantic styles instead:
    • Word Heading 1 style → HTML <h1> tag
    • Word Paragraph with bullet style → HTML <li> element
    • Embedded images in word/media/ → Base64 HTML <img src="data:image/png;base64,..." />

Concise Code Example

docxParser.jsJavaScript
import mammoth from 'mammoth';

// Extract raw text from Word document buffer for AI analysis
export const extractProposalText = async (fileBuffer) => {
    // Extracts plain unformatted text (strips all formatting)
    const result = await mammoth.extractRawText({ buffer: fileBuffer });
    return result.value; // Returns clean string
};

// Convert Word document to semantic HTML for UI Preview
export const convertDocxToHtml = async (fileBuffer) => {
    const result = await mammoth.convertToHtml({ buffer: fileBuffer });
    return result.value; // Returns sanitized HTML string
};
💡 Viva & Examination Questions
Q: Why use Mammoth instead of converting .docx directly via LibreOffice/Word CLI?
A: Mammoth is a zero-dependency, lightweight JavaScript library running natively inside Node.js memory. External converters (like LibreOffice CLI) require heavy headless OS binaries (~500MB+), spawn slow child processes, and preserve complex desktop layout styles rather than clean HTML/text.
Q: Can Mammoth parse legacy .doc (Word 97-2003) files?
A: No. Legacy .doc files use a proprietary binary OLE Compound File Format, whereas Mammoth strictly targets OpenXML format (.docx).

PDF-PARSE

Mental Model: PDF → Extract Raw Text

What & Why

What: pdf-parse is a Node.js library for extracting raw unformatted text streams, page counts, and metadata from Portable Document Format (PDF) files.

Why: Unlike DOCX or HTML, PDFs are strictly visual print representation formats. They do not store text in semantic paragraphs or DOM trees. pdf-parse parses internal PDF vector positioning commands to reconstruct readable text strings for backend text processing.

How It Works Under the Hood (Deep Theory)

PDF Content Stream Parsing & Glyphs Coordinate Ordering

Built upon Mozilla's pdf.js rendering engine core. PDFs store text as absolute graphical draw operations: e.g., BT /F1 12 Tf 72 712 Td (Hello World) Tj ET (Begin Text, set Font F1 12pt, Move to Coordinate X:72 Y:712, Show String "Hello World").

Extraction Algorithm:

  1. Reads the PDF XRef (Cross-Reference) Table at the end of the file to locate page object offset positions.
  2. Parses Page Content Streams and decodes font ToUnicode CMap tables (mapping internal glyph IDs back to UTF-8 characters).
  3. Calculates glyph coordinate matrices $(X, Y)$ on the page plane, ordering text fragments top-to-bottom, left-to-right to reconstruct human-readable paragraphs.

Concise Code Example

pdfExtractor.jsJavaScript
import pdf from 'pdf-parse';

export const processThesisPDF = async (pdfBuffer) => {
    // Execute text extraction pipeline
    const data = await pdf(pdfBuffer);
    
    return {
        numpages: data.numpages,     // Total page count
        info: data.info,             // PDF Metadata (Title, Author, Creator)
        text: data.text              // Extracted raw text string
    };
};
💡 Viva & Examination Questions
Q: Why does text extracted from a PDF sometimes appear scrambled or missing spaces?
A: Because PDFs store text fragments based on absolute visual coordinates rather than semantic sentences. If a PDF lacks a proper ToUnicode CMap, uses custom subset fonts, or uses loose kerning offsets, text ordering algorithms must estimate space characters heuristically.
Q: Can pdf-parse extract text from scanned PDF documents?
A: No. Scanned PDFs store pages as bitmap raster images (JPEG/PNG streams) inside a PDF wrapper. Extracting text from scanned PDFs requires an Optical Character Recognition (OCR) engine like Tesseract.js.

PDFKIT

Mental Model: Programmatic PDF Drawing Engine

What & Why

What: PDFKit is an in-memory PDF generation library for Node.js that exposes a vector drawing API to construct PDF documents from code.

Why: When generating standardized reports, certificates, or marksheets where exact layout positioning, low server memory overhead, and lightning speed are required. PDFKit requires zero external dependencies or browser runtimes (unlike Puppeteer).

How It Works Under the Hood (Deep Theory)

Direct Binary PDF Byte Stream Construction

PDFKit implements the core PDF 1.7 specification natively in JS. A PDFDocument instance is an active Node.js Readable Stream.

When you call imperative vector commands like doc.fontSize(16).text('Evaluation Sheet', 100, 100) or doc.rect(50, 50, 200, 100).stroke(), PDFKit converts these calls directly into raw low-level PDF stream operator codes (e.g. /F1 16 Tf 1 0 0 1 100 742 Tm (Evaluation Sheet) Tj).

Calling doc.end() compiles the internal cross-reference (XRef) binary catalog table and closes the stream, allowing output to pipe directly into HTTP response objects without buffering the entire document in RAM.

Concise Code Example

generateMarksheet.jsNode.js Stream
import PDFDocument from 'pdfkit';

export const downloadMarksheet = (res, studentData) => {
    const doc = new PDFDocument({ size: 'A4', margin: 50 });

    // Direct pipe to Express HTTP Response (Chunked Stream)
    res.setHeader('Content-Type', 'application/pdf');
    res.setHeader('Content-Disposition', 'attachment; filename="marksheet.pdf"');
    doc.pipe(res);

    // Vector Drawing & Text Layout
    doc.fillColor('#1e293b').fontSize(20).text('OFFICIAL MARKSHEET', { align: 'center' });
    doc.moveDown();
    doc.fontSize(12).text(`Student Name: ${studentData.name}`);
    doc.text(`Final Thesis Score: ${studentData.score} / 100`);
    
    // Draw Divider Line (Vector path)
    doc.moveTo(50, 150).lineTo(545, 150).strokeColor('#38bdf8').stroke();

    // Finalize document stream
    doc.end();
};
💡 Viva & Examination Questions
Q: What is the primary memory advantage of piping a PDFKit instance directly to an HTTP response?
A: Streams process data in small chunks. Piping doc.pipe(res) transfers PDF data to the client immediately as byte streams are generated, keeping server RAM consumption minimal regardless of document size.
Q: PDFKit vs Puppeteer: When should you prefer PDFKit?
A: Prefer PDFKit for structured, high-volume programmatic generation (invoices, receipts, marksheets) where speed and low resource usage matter. Puppeteer consumes ~150MB+ RAM per render page; PDFKit consumes only a few megabytes.

PUPPETEER-CORE

Mental Model: Headless Chrome HTML → PDF Engine

What & Why

What: Puppeteer-Core is a Node.js library that provides a high-level API to automate Chrome/Chromium browsers via the Chrome DevTools Protocol (CDP).

Why: When complex document layouts (e.g. styled multi-column evaluation reports, CSS grid charts, modern web fonts) need to be converted to pixel-perfect PDFs. Designing these in PDFKit via manual x,y drawing is extremely painful. Puppeteer lets you render HTML/CSS via Chromium's real Blink layout engine and save it as PDF.

Why puppeteer-core instead of full puppeteer? Full puppeteer automatically downloads a ~300MB bundled Chromium binary on install. puppeteer-core skips the download, leveraging pre-installed host Chrome/Chromium (essential for lightweight Docker images).

How It Works Under the Hood (Deep Theory)

Chrome DevTools Protocol (CDP) WebSocket Automation

Puppeteer-Core spawns an existing Chrome executable in headless mode (no GUI window) with remote debugging enabled over a WebSocket port.

PDF Generation Sequence:

  1. Connects via WebSocket to CDP endpoint.
  2. Sends Target.createTarget command to open a blank tab (Page).
  3. Injects HTML string into DOM via Page.setPageMarkup and waits for network idle state (fonts & images loaded).
  4. Triggers Chrome's native print engine via CDP command Page.printToPDF, using Chromium's Blink layout engine and Skia graphics library to rasterize CSS to vector PDF page formats.

Concise Code Example

htmlToPdfService.jsPuppeteer Automation
import puppeteer from 'puppeteer-core';

export const renderHtmlToPdf = async (htmlContent) => {
    // Launch pre-installed Chromium instance
    const browser = await puppeteer.launch({
        executablePath: process.env.CHROME_PATH || '/usr/bin/chromium-browser',
        args: ['--no-sandbox', '--disable-setuid-sandbox']
    });

    const page = await browser.newPage();
    
    // Inject HTML content and wait for asset loading
    await page.setContent(htmlContent, { waitUntil: 'networkidle0' });

    // Render Chromium print engine to PDF buffer
    const pdfBuffer = await page.pdf({
        format: 'A4',
        printBackground: true, // Preserve CSS background colors
        margin: { top: '20mm', bottom: '20mm' }
    });

    await browser.close();
    return pdfBuffer;
};
💡 Viva & Examination Questions
Q: What is the main difference between 'puppeteer' and 'puppeteer-core'?
A: puppeteer automatically downloads a specific Chromium binary during npm install (~300MB download). puppeteer-core does not download a browser and requires an explicit executablePath pointing to an existing browser installed on the host OS.
Q: How do you prevent multi-page PDF tables from cutting text rows in half in Puppeteer?
A: Using CSS page-break print styles: tr, .card { break-inside: avoid; page-break-inside: avoid; }.

NODEMAILER

Mental Model: SMTP Email Dispatcher

What & Why

What: Nodemailer is a zero-dependency module for Node.js applications to send emails using Internet standards (SMTP, Sendmail, SES).

Why: Automated transactional communication (sending password resets, defense date notifications, supervisor assignment emails). Nodemailer handles complex MIME encoding, multi-part body structures (plain text + HTML fallbacks), and attachment streams seamlessly over TLS socket connections.

How It Works Under the Hood (Deep Theory)

SMTP RFC Protocol Handshake & Socket Connection Pooling

Nodemailer implements RFC 5321 (SMTP protocol) and RFC 5322 (Internet Message Format) over native Node.js net and tls sockets.

SMTP Transaction Lifecycle:

  1. Connection / EHLO: Establishes TCP/TLS connection with SMTP server (e.g. Gmail smtp.gmail.com:587) and exchanges EHLO capabilities.
  2. TLS / Auth: Upgrades connection to secure TLS via STARTTLS and sends AUTH LOGIN or AUTH PLAIN base64 credentials.
  3. Envelope Negotiation: Transmits MAIL FROM:<sender@univ.edu> and RCPT TO:<student@univ.edu>.
  4. MIME Data Chunking: Formats HTML/text body and encodes binary attachments into Base64 boundary chunks inside the DATA stream command. Terminated by \r\n.\r\n.
  5. Connection Pooling: Setting pool: true reuses open TCP/TLS socket connections across multiple email dispatches, avoiding repeated SSL handshake overhead.

Concise Code Example

emailService.jsNodemailer Transport
import nodemailer from 'nodemailer';

// Create reusable pooled SMTP connection transporter
const transporter = nodemailer.createTransport({
    host: process.env.SMTP_HOST,
    port: 587,
    secure: false, // Upgrade via STARTTLS
    pool: true,    // Reuse TCP connection sockets
    auth: {
        user: process.env.SMTP_USER,
        pass: process.env.SMTP_PASS
    }
});

export const sendEvaluationNotice = async (recipientEmail, studentName) => {
    const mailOptions = {
        from: '"Thesis Committee" <no-reply@university.edu>',
        to: recipientEmail,
        subject: 'Thesis Proposal Evaluation Scheduled',
        text: `Hello ${studentName}, your evaluation has been scheduled.`,
        html: `<h3>Hello ${studentName}</h3><p>Your thesis evaluation has been <b>scheduled</b>.</p>`
    };

    const info = await transporter.sendMail(mailOptions);
    return info.messageId;
};
💡 Viva & Examination Questions
Q: What is the benefit of enabling 'pool: true' in Nodemailer transports?
A: Instead of creating and tearing down a new TCP connection and performing a cryptographic TLS handshake for every single email, socket pooling keeps a persistent pool of open connections, drastically speeding up bulk notification dispatch.
Q: How does Nodemailer support email clients that cannot display HTML?
A: It formats the payload as a MIME multipart/alternative message containing both a text/plain version and a text/html version. The client software chooses the highest fidelity format it supports.

EXPRESS-RATE-LIMIT

Mental Model: Protect APIs from Abuse

What & Why

What: Express-Rate-Limit is request-throttling middleware for Express applications designed to limit repeated hits to API endpoints.

Why: Essential security defensive layer against Brute-Force login attacks, API Denial of Service (DoS), and resource cost protection on CPU-intensive endpoints (e.g. Puppeteer PDF rendering or AI parsing routes).

How It Works Under the Hood (Deep Theory)

Sliding Window Algorithm & Key Generation

Acts as an Express middleware pipeline gatekeeper: (req, res, next).

  1. Key Identification: Generates a client identification key (by default req.ip).
  2. Counter Store Lookup: Fetches request hit counter from a Store engine (default: MemoryStore hash map).
  3. Window Evaluation: Checks if request count within current timeframe window (windowMs) exceeds max threshold.
    • If within limit: Increments hit counter, sets HTTP headers (RateLimit-Limit, RateLimit-Remaining), and invokes next().
    • If exceeded: Short-circuits execution and immediately returns HTTP 429 Too Many Requests along with a Retry-After header.

Concise Code Example

rateLimiter.jsExpress Middleware
import rateLimit from 'express-rate-limit';

// 1. Strict Limiter for Auth Routes (Anti Brute-Force)
export const authLimiter = rateLimit({
    windowMs: 15 * 60 * 1000, // 15 minutes window
    max: 5,                  // Max 5 login attempts per IP
    message: { error: 'Too many login attempts. Please try again after 15 minutes.' },
    standardHeaders: true,   // Return RateLimit-* headers
    legacyHeaders: false
});

// 2. Moderate Limiter for Heavy PDF Generation
export const pdfGenLimiter = rateLimit({
    windowMs: 60 * 1000,      // 1 minute window
    max: 10,                 // Max 10 PDF generation calls
    message: { error: 'PDF generation quota exceeded. Slow down requests.' }
});
💡 Viva & Examination Questions
Q: What major flaw occurs when using default MemoryStore rate limiting in a multi-instance or clustered Node app?
A: MemoryStore maintains hit counters in local Node process RAM. In a clustered environment behind a load balancer (e.g. Nginx, PM2 cluster, Kubernetes), consecutive user requests land on different processes, allowing clients to bypass limits. Solution: Use a centralized store like rate-limit-redis.
Q: Why must you configure 'app.set("trust proxy", 1)' when running Express behind Nginx or Cloudflare?
A: Without trust proxy, Express sees the IP of the reverse proxy (Nginx) as req.ip for EVERY user request. This causes the rate-limiter to treat ALL system users as a single IP, blocking the entire site globally once the limit is reached.

💡 Viva & Examination Questions on Call Hierarchy
Q: How does data flow from the student's PDF upload to the AI Chatbot drawer in the coordinator's view?
A: 1) Student uploads PDF via Forms.jsx or Groups.jsx. 2) Backend uploadController.js saves file locally via Multer and makes an asynchronous fire-and-forget HTTP call to FastAPI's /api/ai/analyze. 3) FastAPI processes the PDF using PyMuPDF, creates 384-dimensional dense vectors with sentence-transformers, and stores them in ChromaDB. 4) When the coordinator opens the AI drawer, the frontend connects to /api/ai/chat/stream, where FastAPI queries ChromaDB for top-$k$ passages, augments the prompt, and streams LLM tokens via Server-Sent Events (SSE).
Q: How does the system guarantee that coordinator actions never leak across degree programs?
A: It uses a two-tier guard: On the frontend, DegreeGuard.jsx checks user.degreeType and blocks navigation to unauthorized degree URLs. On the backend, utils/coordinatorScope.js resolves the coordinator's exact programId (e.g. BCT) from the database and injects strict Prisma query filters (where: { programId: coordinator.programId }), ensuring API requests cannot access or mutate foreign program records even if URL parameters are manipulated.
